# 余白

メニューバーの「実空き」は、内蔵SSDで今空いている容量です。クリックすると「macOSの利用可能見込み」も表示します。これは、必要に応じて解放できる領域も含め、重要な書き込みに使えるとmacOSが見積もった容量です。ウインドウを閉じても実空きとメモリ負荷は約30秒ごとに更新されます。アプリを終了するにはメニューバー表示を右クリックします。

### ストレージ

「再計測」で開発用キャッシュとシステムの対象領域を調べます。測定値は対象が占有する容量です。フォルダ全体を調べた行と、対象形式のファイルだけを調べた行があります。各行の説明で範囲を確認できます。2回目以降は同じ対象の前回比が出ます。

- **Python・uv** は公式の `uv cache prune` を使用します。適合するローカル実行ファイルとキャッシュがある場合に、確認して実行できます。処理後に内蔵SSDの空きを再計測します。[uvのキャッシュ管理](https://docs.astral.sh/uv/concepts/cache/#clearing-the-cache)
- **診断レポートとHomebrewの配布ファイル** はファイルを選択して扱います。ユーザーの対象はゴミ箱へ移動します。システムの診断レポートはFinderで選択し、macOSの権限のもとで操作します。ゴミ箱への移動量と実際のSSDの空きの増減は別々に確認してください。
- **シミュレータ** はXcodeのランタイムと登録端末を照合します。使っていない端末を含め、登録のあるランタイムは利用状況を表示します。端末がなく、Xcodeの条件を満たすランタイムだけを選んで取り除けます。
- **Time Machine** は内蔵Dataボリュームのローカル復元点の件数を表示します。専有サイズを知りたいときはディスクユーティリティでDataボリュームを選び、「表示」→「APFSスナップショットを表示」を開きます。

### 案件別

「フォルダを選ぶ…」でローカルの案件を指定します。開発用の既知のフォルダを探し、対象ファイルの割当容量を表示します。動画を書き出したりゲームをビルドした後に「同じ案件を再計測」すると増えた場所を確認できます。計測上限や権限のため不完全な行に前回比は表示しません。前回の数値はこのMacのアプリ設定に最大12範囲まで保存されます。

「大容量の重複を調べる…」は、選んだ案件内の対応する動画・音声・画像・ビルドファイルについて、同じサイズの候補の内容をSHA-256で照合します。結果からFinderで実物を確認できます。複数の案件が必要とする同一素材やAPFSのクローンもあるため、一致した容量を解放見込みに足すことはできません。

### 作業コピー

メニューバーの「余白」をクリックして「作業コピー」を選びます。右クリックの「作業コピーとブランチ」からも直接開けます。ウインドウ内では ⌘2 が使えます。

案件ごとに、本体以外の作業コピー、ローカルブランチ、Gitの登録から外れたフォルダを表示します。週次レポートと同じ登録案件をその場で調べます。清掃除外に指定した案件はGitの登録情報だけを表示します。

「操作」→「Gitの案件を選ぶ…」で別の案件も開けます。読み込んだ案件は次回も開き、「登録案件に戻る」で一覧に戻せます。デスクトップにある案件を初めて調べるときは、macOSがフォルダへのアクセスを確認する場合があります。すでに作成した週次レポートは、画面下のリンクからいつでも開けます。

作業を終えたコピーは、表示された状態を確認してから1件ずつ閉じられます。確認後にブランチやコミットが変わると操作を保留します。ブランチを整理した場合も、結果に表示される復元コマンドをコピーできます。ファイルやフォルダを比較するときは、比較したいコピーと残す原本を選びます。詳しい保護条件と復元手順は[作業コピーの手順](../docs/workspaces.md)にあります。

### データ索引

「データ索引」で登録案件を開くか、別の案件フォルダを選びます。「作業コピー」の案件詳細からも索引に移れます。対象の行で「用途を記録…」を押し、担当、理由、見直す条件を保存します。コピーには残す原本、一時生成物には再生成手順も記録できます。登録済みのコピーは「原本と照合」で、その時点の内容を比較します。[記録の保存先と判定の意味](../docs/project-index.md)

### メモリ

上位アプリには計測できた子プロセスを含みます。「通常終了…」では選んだアプリに終了を依頼し、実際に終了したかを確認します。直後のMac全体の空きRAM・スワップ・メモリ負荷には同時に動いているほかの作業の影響も含まれます。負荷はmacOSのメモリプレッシャーに基づきます。[Appleのメモリ使用状況の説明](https://support.apple.com/ja-jp/guide/activity-monitor/actmntr1004/mac)

### ビルドと動作確認

```sh
python3 headroom/install.py
open ~/Applications/余白.app
python3 headroom/test.py --gui
```

テストは専用の一時データを使います。`--gui` はテスト専用アプリを実際に起動し、終了の取り消しと正常終了を検証するため、ログイン済みのMacで実行します。アプリに常駐サーバーやログイン項目を追加する処理はありません。

### 初版の検証基準

一般的な容量マップ、メニューバー監視、再生成物の検出は既に各製品にあります。余白では、動画・ゲーム・AI開発の作業領域を識別し、計測間の増減と整理後の空きを追えることを評価します。[DaisyDisk](https://daisydiskapp.com/specs/)・[CleanMyMac Menu](https://macpaw.com/support/cleanmymac/knowledgebase/cleanmymac-menu)・[Moleの開発用フォルダ検出](https://github.com/tw93/Mole/blob/V1.72.0/lib/clean/purge_shared.sh)・[DevCleaner](https://github.com/vashpan/xcode-dev-cleaner)

| 確かめること | 合格条件 |
| --- | --- |
| 動画・ゲーム・開発の作業フォルダ | 選んだ案件のRemotion、Godot、Node.jsの領域が出て、元素材との共有ハードリンクを二重に数えない |
| 大容量ファイルの重複 | 同じサイズで中身が違うファイルを候補に含めない |
| 手動の整理 | スキャン後に変更されたファイルと開いているファイルを保持し、移動したテストファイルをゴミ箱から復元できる |
| システム管理データ | ランタイムと端末の情報を照合し、状態が変わった場合や利用状況を調べられない場合は削除しない |
| メモリの解放 | テストアプリが終了を断った場合と、実際に終了した場合を区別し、実測結果が画面に出る |

実機の比較では、同じ模擬案件に8種類のフォルダを用意しました。余白の案件計測は8種類すべてを表示し、Mole V1.72.0 のプロジェクト用候補検出関数は5種類を返しました。両方で出たのは `.next`、`.pytest_cache`、`.venv`、`build`、`node_modules` です。余白ではさらに `.godot`、`.render-bundle`、`.render-tmp` が出ました。実験ではMoleの走査先と書き込みを一時領域に限定し、両者の対象パスとデータを揃えています。余白は確認用の一覧、Moleは整理の適格性を考慮する候補一覧を返します。この比較の評価項目は掲載範囲です。[比較したMoleの処理](https://github.com/tw93/Mole/blob/V1.72.0/lib/clean/project.sh)
