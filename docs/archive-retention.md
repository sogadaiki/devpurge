# アーカイブの10日ルール

対象は `archive_root` で明示指定した一つのフォルダ。名称にarchiveやアーカイブが含まれるだけの他のフォルダは対象外。既定は無効で、`archive_auto=1` の設定が継続的な削除承認になる。

このMacではユーザーが2026-10-10に `~/Desktop/アーカイブ` へ移した後、10日触っていないファイルの削除を承認した。一般のreview候補を削除する権限や、証拠・契約書等の保護を解除する権限には広げない。

## 時間の判定

- ファイル単位で、初回登録と最後に観測した利用・変更を保存する。
- `max(初回登録, 最終利用・変更) + 10 × 24時間` 以降に、次の通常パージで期限切れにする。
- 移動直後に `devpurge archive --track` を実行する。これにより、元のファイルが古くても10日未満で消えない。
- 未登録の既存ファイルは初回登録時から数える。フォルダ名の日付、birthtime、mtimeやSpotlightのDateAddedだけでは実際の移動を証明しない。
- 更新・変更・アクセス時刻、SpotlightのLastUsedDate、使用中ファイルを確認する。観測の間に内容やメタデータが変われば、検出時点から10日延長する。名前変更や同名別ファイルへの置換も新規登録として扱う。
- 台帳を読むだけの再スキャンやディレクトリ列挙では期限を延ばさない。通常の重複検出がアーカイブをハッシュ読み取りして期限を延ばし続けることも防いでいる。
- OSに利用が記録されない場合もある。エージェントがアーカイブを再利用するときは、読む・編集する前に `devpurge archive --touch <対象パス>` で期限を延ばす。

## 残すもの

証拠・裁判・原本・契約書等の既存保護パターン、rcの `protect=` / `exclude=`、`.env*`、Git管理フォルダを含む作業コピー、`.devpurge-keep` を置いたフォルダ以下、シンボリックリンク、ハードリンク、別ボリューム、特殊ファイル、使用中ファイルは保持する。判断・走査・利用情報取得に失敗した場合も保持する。

対象はファイル単位。保護された子ファイルがある案件でも、その保護対象を残し、条件を満たす他のファイルだけが期限切れになる。アーカイブのルートやworktreeを再帰削除することはない。通常キャッシュ削除のホワイトリストにもアーカイブは追加しない。

## コマンドと実行時の記録

| コマンド | 実際の動作 |
|---|---|
| `devpurge archive --dry-run` / `--json` | 候補数・保持理由を読む。台帳作成・更新や削除なし |
| `devpurge archive --track` | 新規到着と利用状況を台帳に記録。削除なし |
| `devpurge archive --touch <path>` | 既存ファイルまたはフォルダ以下の期限を延長。削除なし |
| `devpurge archive --expire` | opt-in済みルートの期限切れファイルだけを削除 |
| 通常の `devpurge` / `-y` | 新規登録、候補表示、選択されたArchive行の期限切れ整理 |
| 通常の `--trash` | 期限切れファイルをゴミ箱へ移動。空き容量の即時回復ではない |

単独のアーカイブ操作は他のキャッシュ、30日quarantine、Time Machine、ブランチに作用しない。`--ai-only`、`sudo`、未設定・無効化時には自動期限切れを行わない。新たなlaunchdや通知ジョブは作らない。

状態は `~/Library/Application Support/devpurge/archive/state.json`。同時実行はロックで拒否する。実行直前に計画の一致、使用状況、実体・サイズ・時刻、物理パスを再確認する。削除はディレクトリ記述子を使い、親のシンボリックリンク経由で対象外に抜けない。

月別 `deletions-YYYYMM.jsonl` に実行前と成功・失敗を区別して残す。削除済みファイルは台帳から除き、再実行しない。候補の割当サイズと実測の空き容量差は別の指標。バックアップはこの機能の前提として自動検証したり作成したりしない。

## 共通スキルとfinish

正本はこのリポジトリの `skills/archive-cleanup/SKILL.md`。Macの `~/.claude/skills/archive-cleanup` から正本を参照し、Codexは既存の `~/.codex/skills/claude-home` 共通経路を通じて同じ内容を使う。

finish時にタスクの権限内でアーカイブへ移した場合は、このスキルで `--track` を実行する。`finish-session` だけを根拠に未完了データをアーカイブへ移したり、必要な参照を壊したりしない。再利用時は `--touch`。期限切れ整理は既存devpurge実行とアーカイブ整理依頼で行う。
